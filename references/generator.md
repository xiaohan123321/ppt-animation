# 生成器：一份 spec，长出 N 套片子

`scripts/gen_deck.py` 不做"填空"。它按 seed 从词表里**抽**锚点、形状、母题、底图、动效，
再按约束组装每一页 —— 同一份内容，seed 不同就是三套风格不同、结构依然成立的片子。

```
python scripts/gen_deck.py assets/spec_demo.json --seed 7 --out build/s7
```

产出四样东西，一次成型：
- `deck.pptx` / `plan.json`（spid 是生成时记下的真实 id，永远不会对不上）
- `deck_动效版.pptx` —— plan 的时间轴已烘焙进 pptx，放映即有全套动画/转场
- `bg/*.jpg|png` —— 每页的远层 / 近层 / 窗口浓墨版

## spec 格式

```json
{
  "palette": "qinglv",            // 可省略；省略则按 seed 随机
  "meta": {
    "kicker":   "2026 全国大学生职业规划大赛 · 校赛作品",
    "title":    "以数为舟　向智而行",     // 封面主标题，走毛笔行楷
    "subtitle": "大学生职业生涯规划书",
    "en":       "COLLEGE STUDENT CAREER PLANNING",
    "author":   "张明 / 人工智能学院 · 人工智能 · 2024 级",
    "end_title": "把「想做的」变成「正在做的」",
    "end_lead":  "职业规划不是一次决定，是一套持续校准的方法。"
  },
  "pages": [ ... ]
}
```

### 页类型

| type | 必备字段 | 说明 |
|---|---|---|
| `cover` | — | 全幅底图 + 居中书法标题，不画窗口 |
| `toc` | `items:[[号, 中文, 英文, 一句话]]` | 目录 |
| `chapter` | `no, title, lead`，可选 `body/items/quote` | 章节页 |
| `bullets` | `title, rows:[[标记, 分值, 名称, 说明]]` | 带序号条目，可加 `evidence/foot` |
| `bars` | `title, bars:[[名称, 分值]]` | 条形图，有 60 分基准线 |
| `cards` | `title, cards:[[标题, 正文]]` | 2×N 卡片 |
| `timeline` | `title, steps:[[年, 阶段, 动作, 产出]]` | 竖向时间轴 |
| `closing` | 可选 `title/lead` | 浓墨满版收尾 |

所有页可带 `eyebrow`（眉标）、`lead`（导语）、`evidence`（底部三栏）、`foot`（脚注）。

## 跨页融合（"上下页咬在一起"）

四条规则，缺一条就会"跳"：

1. **整套共用一张背景**。背景每页不同 → 转场无论怎么调，切的那一帧都会跳一下。
   现在开篇只画一张 `bg/main_far.jpg` + `main_near.png`，所有页都引用它 ——
   背景像素完全一致，`cut` 就等于没切。**变化交给窗口里的景**（每页换 seed，仍是同一画风）。
   底图画法 6 种：`mount` / `mist` / `ridges` / `ink` / `grid` / `yuan`。
2. **雾白也必须一致**。内容页和封面都压同样的 16%（`yuan` 全幅底图加重到 30%，
   山体铺满整页后只有重纱才保得住正文对比），否则整页色阶会在切页时闪一下。
2b. **远景演变（参考图4/5）**。每页背景记为 `bg` 角色，plan 里第一条就是
   `push`：9s 单程 100%→114% 慢推近（Ken Burns，只进不退）—— 放映时整幅
   山水缓缓压向观众，就是"一张幻灯片里的远景演变"。近层视差山不推，
   远推近停正好做出纵深。
3. **环的层数恒定**。`motif_rings` 固定 6 层（缺口角度上限压到 300°），
   这样跨页 carry 时"上一页的第 3 层"能对上"本页的第 3 层"，读起来是同一组环在变，
   而不是一套环消失、另一套环出现。
4. **内容比接力早 60ms 起**。`t = base - 60 + i*52`：窗口还在滑，第一行字已经淡入，
   两页在时间轴上咬在一起 —— 这是"融合"的手感，比"滑完再出字"连贯得多。

配套：转场一律 `cut`（这点没变），所有运动由 `carry` 承担；环和斜刃额外 `turn` 一圈。

## 环的五种结构 + 逐层错峰的接力

之前"环"只有一套同心圆，只是参数在变 —— 那叫调参，不叫多样。现在环有**八种结构 DNA**，
每页抽一种（层数固定 6：厚带/缘线各半，保证跨页 carry 能一层对一层）。
画法是**实心厚带（blockArc）× 细缘线交替镶嵌** —— 带子是一块块"环形砖"，
不再是细线堆叠；缺口对齐同一族方向，远看是铸铁环，近看每层有阶梯：

| 变体 | 结构 | 观感 |
|---|---|---|
| `classic` | 同心阶梯，缺口全朝文字侧 | 最稳的镜头卡口 |
| `eccentric` | 每层圆心沿一个方向递进偏移（外层偏 0.10d） | 环"歪"成三维筒 |
| `spiral` | 缺口逐层再转 40° | 光圈拧进来 |
| `wedge` | 第二道换成一段 62° 的厚楔 | 光圈叶片咬住 |
| `lens` | 最内加一道半透明厚带压住照片缘 | 照片镶进环座 |
| `bisect` | 两组带各三层，第二组错开 0.30d | 双镜头 |
| `segments` | 五段厚砖排开，每段 46°，中间留缝 | 抱死的刹车盘 |
| `orb` | 缺口收到最小，靠透明度分层 | 全环仪表 |
| `pacman` | 一道巨厚环咬掉 100° 大楔口 + 缘线收边 | 吃豆人（章节页专用） |

封面另有一套独立的**虹膜环阵**（`ring_lattice`）：5 道厚环同心等距排开、
每道拆成 4 段 82° 象限弧，象限间的 8° 缝对齐横竖轴形成"十字缝"，
整组压在居中标题底下；入场逐段 `turn` 整转 = 光圈打开。
目录小圆窗是**四象限棋盘**（对角同色纸白/墨 + 中心墨盘托编号）；
章节页固定 `pacman` 大环，且**下一章编号从页边探头**（对角呼应）。
旧名 `ticks` / `reticle` 自动映射为 `lens` / `orb`。

**环筒是每一页的底**。`dots` / `blades` / `arcset` / `eclipse` 这些不再是独立母题，
而是叠在环筒上的一层点缀 —— 之前抽到它们时整页几乎看不到环，就成了"这页没有环"。
现在只有"环筒"和"环筒 + 点缀"两种。

**叠式（`motif_stack`）—— 图形上下重叠**。每个内容页（章节除外）再叠一层直接
压住照片的图形，打破"环永远在外围"的单层感，四种画法每页随机：
`cross_band`（实心横带横贯照片 + 骑缝纸线）/ `disc_shift`（半透明错位盘
垂直偏 0.33d 从照片上/下缘长出来）/ `shingle`（三道横带纵向叠瓦、相互搭接）/
`moon`（只露一半的粗环带扣在照片缘上）。叠式记为 kernel，跨页 carry 时
跟着照片一起滑 + turn 旋转 —— 重叠体在页面之间是"搬过去"的，不是消失再出现。

**配色 9 套**：`qinglv` 青绿 / `daiqing` 黛青 / `zhejin` 赭金 / `yanhui` 烟灰 /
`qingci` 青瓷 / `zitan` 紫檀 / `songlv` 松绿 / `xuantie` 玄铁（冷钢灰+铁锈橙）/
`jiangzhu` 绛朱（深红棕+鎏金）。spec 写 `"palette": "xuantie"`，或 CLI
`--palette xuantie` 覆盖。

**窄空间自动换挡**：`limit`（圆心到文字栏的距离）小于 210 时，`classic/eccentric/spiral/bisect`
会被缺口吃掉只剩两段小弧 —— 这种情况直接换成 `segments`，短弧成组在窄空间里反而立得住。

**接力也改了**。以前六层同一时间、同一时长地滑过去，看起来就是"一个整体平移"。现在：

- **照片先到，环按远近逐层追上来**：carry 延迟 0 / 80 / 122 / 164 / 206 / 248 …（每层 +42ms）
- **每层转速不同**：turn 时长 900 / 1010 / 1120 / 1230 / 1340 / 1450 ms，
  内环转得快、外环转得慢 —— 六层转出一个"错位光圈"，不是一根棍子整体转
- **落位后最外层继续慢摆**（`sway6` 7s），画面一直是活的

⚠️ 这一层的效果预览 GIF 里看不到：`render_deck.py` 把圆窗当**一个图层**合成，
不区分每层环的时间差。要看到真正的错峰，得让预览器按 spid 逐层合成（待做）。
PPT 文件里是真的。

## 多环叠加怎么做的

`motif_rings` 画的是"镜头筒"而不是一圈线：**六层同心环，粗细/明暗/虚实都不同**，
半径从 0.90 到 1.60 倍，厚环段与细环交替，再叠一道更淡的宽环压在照片上。

关键在**每层按文字边界自动让缺口**：圆心沿缺口方向到文字栏有个距离 `limit`，
当某层的半径（含线宽的一半）超过它时，用 `acos(limit/r)` 算出被遮挡的角度，
把那段弧挖掉。所以环可以画得很大，但**绝不会横穿正文** —— 这是"多环"能成立的前提。
缺口角度超过 320° 的层直接跳过（已经基本被挡完了，留着只是残渣）。

斜刃（`blades`）同理：刃是以圆心为中心的长条，半长被压到 `limit*0.925` 以内。

## 文本自适应（这一版的核心）

PowerPoint 没有文本测量 API，所以 `deckgen_kit` 里做了一套估算：

- `line_count()` 按字符累加宽度（中文 1.0em、数字 0.56em、西文 0.52em）算折行；
- `fit_size()` 二分出"最大且放得下"的字号（下限 5.5pt）；
- `atxt()` = 自动字号 + 还放不下就 `truncate_to()` 截断加省略号。

**所有正文都走 `atxt`，没有一处写死字号。** 于是长文只会变小，不会压住下一块。
生成结束会打印一行警告，列出哪些页的文本框被压缩过 —— 要改内容就照着那几页改。

## 约束（生成时自动守）

- **站位**：左/右必须交替、相邻页直径不能相同、位移不足 0.40 屏宽就重抽。
- **上下站位**要同时满足：文字带 ≥220pt、条目 ≤4 个；否则退回左右。
  因为上下是"宽而矮"的盒子，条目一多必然挤。
- **文字栏**由锚点反推；母题只在窗口那侧生长，绝不进文字栏。
- **证据带 / 脚注**在盒子高度不足（<300 / <260）时不画，避免和正文抢地方。
- 内容页压 16% 雾白，封面/收尾不压（要画意）。
- 转场一律 `cut`：运动全交给 `carry`。
- 动效：`carry`（窗口从上一页滑来 + 直径插值）+ 弧线/环 `turn` 一圈
  + 内容每 52ms 一条 + 页边装饰最后泛起。

## 已知边界

- 内容块是**单列**的。上下站位那种"宽而矮"的区域，只靠缩字号硬塞，
  条目超过 4 个就退回左右 —— 想要真正的上下版式，得给块加"双列重排"。
- 母题参数是手调过的几组常量，不是连续空间；同一种母题出现两次能认出来。
- 表格、图片墙、真正的图表（chart 对象）还没做。
- 底图是程序画的，放大到特写能看出渐变层；要"真照片"得换素材。
- 字体依赖本机（华文行楷 / 华文中宋），换机器会回退。
