# 电影感 PPT 动画引擎 · 参数与转场指南

本引擎直接重写 PPTX 的 `p:timing`、`p:spPr/a:effectLst` 与 `p:transition`。
它不依赖 PowerPoint 的动画 UI，因此能精确控制时长、延迟、缓动、循环与转场。

## 先做三步检查

1. `python scripts/inspect_slides.py <pptx> shapes.json`
   看真实画幅、spid、形状名称、图片、文本、组合与视觉角色。
2. 在 PPT 里把关键角色命名清楚：`camera_ring`、`bg_hero`、`title_main`、
   `card_1` 等。名称稳定，Morph 与后续维护才稳定。
3. 先做静态页，再加动画。动画只负责“如何进入”，不能修补混乱的版式。

## plan 格式

旧数组写法保持兼容：

```json
["8", "iris", 1100, 100]
```

第五项可放缓动参数：

```json
["8", "cinematic", 900, 120, {"ease": "out"}]
```

推荐对象写法，字段更清楚：

```json
{"spid": "8", "effect": "iris", "dur": 1100, "delay": 100, "ease": "out"}
```

`ease` 可取 `out`、`in`、`smooth`、`linear`。默认 `out`，适合大多数入场。

## 页内效果（32 种）

### 入场（25 种）

| effect | 行为 | 适用 |
|---|---|---|
| `fade` | 淡入 | 底色、正文 |
| `carry` | 从指定偏移处滑回原位（`dx/dy` 画布比例，可选 `scale`） | **跨页接力**：圆窗从上一页位置滑过来 |
| `turn` | 只转 360°，不缩放 | 配 `carry`，让弧线边滑边拧 |
| `wheel` | 轮盘扇形揭示 | 圆形转场、光晕涟漪 |
| `iris` | 圆形遮罩从中心展开 | 电影感圆形推进、图片揭示 |
| `circle` | 圆形展开 | 与 `iris` 接近，保留兼容 |
| `wipe_r/l/d/u` | 方向擦除 | 进度条、轴线、竖条 |
| `zoom` | 0%→100% 真缩放 + 淡入 | 卡片、图标、照片 |
| `zoom_soft` | 40%→100% | 标题、数字、圆环 |
| `zoom_turn` | 72%→100% + 8° 回正 | 标题、章节字 |
| `cinematic` | 86%→100% + 3.5% 上移 + 3° 回正 + 淡入 | 巨号数字、封面主视觉 |
| `spin` | 缩放 + 360° 旋转 | 需要强旋转的装饰 |
| `float` / `rise` | 从下方 6% 浮入 + 淡入 | 标题、卡片、正文 |
| `fly_l/r/t/b` | 从屏幕外飞入 | 章节切换、强提示 |
| `box` | 盒状展开 | 图形从中心出现 |
| `diamond` | 菱形展开 | 图标、装饰 |
| `blinds` | 百叶窗 | 图片、大色块 |
| `split` | 中心分割 | 上下对开 |

### 强调循环（7 种）

| effect | 行为 | 建议时长 |
|---|---|---|
| `pulse` | 缩放 +11% 呼吸 | 1200~1800ms |
| `breathe` | 缩放 +3.5% 轻呼吸 | 1600~2400ms |
| `kenburns` | 缩放 +6.5% 慢推近 | 6000~10000ms |
| `sway` | ±3.2° 轻摆 | 1600~2400ms |
| `rotate` | 360° 持续旋转 | 10000~20000ms |
| `drift_x` | 水平 ±1.2% 漂移 | 6000~10000ms |
| `drift_y` | 垂直 ±1.2% 漂移 | 6000~10000ms |

同一 spid 可以出现两次：先入场，再强调。

```json
["4", "zoom_soft", 900, 120],
["4", "rotate", 14000, 1020]
```

`carry` 的写法（注意 dx/dy 放在第 5 项的选项里）：

```json
["3", "carry", 1000, 0, {"dx": 0.65, "dy": 0, "scale": 114.0, "ease": "out"}]
```

## 页面转场（38 种）

每页 plans 增加：

```json
"transition": "morph",
"transition_spd": "slow"
```

`transition_spd`：`fast` 约 350ms、`med` 约 600ms、`slow` 约 1000ms。
也可写 `"transition_ms": 900` 精确控制 GIF 预览时长。

| 类别 | 名称 |
|---|---|
| 淡化/切换 | `fade`、`cut`、`dissolve`、`newsflash` |
| 推入 | `push_u/d/l/r` |
| 擦除 | `wipe_u/d/l/r` |
| 覆盖/揭开 | `cover_u/d/l/r`、`uncover_u/d/l/r` |
| 分割 | `split_h`、`split_h_out`、`split_v`、`split_v_out` |
| 圆形 | `circle`、`iris`、`wheel` |
| 门/百叶/棋盘 | `doors_h/v`、`comb_h`、`blinds`、`checker`、`strips` |
| 其他 | `zoom`、`plus`、`wedge`、`random`、`morph`、`none` |

### Morph 的正确用法

1. 相邻页保留一个同名形状，例如 `camera_ring`。
2. 在 plans 每页声明：

```json
"morph": [{"spid": "4", "name": "camera_ring"}]
```

3. 让圆环在两页之间改变位置、尺寸或旋转。Morph 会连续变形。
4. 不要把同一页所有文字都设成同名；只让一个核心视觉元素延续。

没有可靠同名形状时，优先用 `iris` 或 `wheel`，它们比伪造 Morph 更稳。

## 形状特效

plans 每页可配置：

| 字段 | 作用 |
|---|---|
| `glow: [spid...]` | 纯色填充改成径向透明辉光 |
| `glow: {"spid": {"color": "F4C76A", "a1": 60, "a2": 0}}` | 指定辉光颜色与中心透明度 |
| `shadow: {"13": 24}` | 外阴影，单位磅 |
| `shadow: {"13": {"blur": 24, "dist": 3, "alpha": 38, "direction": 90}}` | 完整阴影参数 |
| `soft: {"8": 4}` | 柔化边缘；慎用，超过 5 磅容易发雾 |
| `solid: {"9": ["D4AF37", 80]}` | 改纯色填充与不透明度 |
| `outline: {"20": ["F4C76A", 1.5]}` | 改描边颜色与磅数 |
| `delete: [spid...]` | 删除测试标记或多余形状 |

## 关键坑位

1. **spid 是 `cNvPr@id`**，不是 python-pptx 的字符串 shape id。
2. **图片也要参与编排**：新版 `shape_map` 已包含 `p:pic`、`p:grpSp`、
   `p:graphicFrame`、`p:cxnSp`。
3. **柔化边缘会糊**：光晕优先用 `glow`，不要叠多层大 `softEdge`。
4. **Morph 依赖同名形状**：不同名时 PowerPoint 只能做普通淡入淡出。
5. **深色背景页要设纯色底**：如果背景图先 fade 入，幻灯片底层若是白底会闪白。
6. **背景图建议作为全页 `p:pic`**：这样能单独做 `kenburns`、`drift_x/y`；
   静态 `p:bg` 也可以渲染，但动画只能作用在形状上。
7. **预览不是 PowerPoint 内核**：GIF 用于检查节奏、层级与构图；最终效果仍应在
   PowerPoint/WPS 中播放确认。
8. **动画位移用 path，不要写 `#ppt_x` 表达式**：`p:animMotion@path` 才是规范路径，
   `p:from/p:to` 的 x/y 是整数百分比。推荐 `path="M 0 0.06 L 0 0"`。
9. **循环回弹属性是 `autoRev`**，不是 `autoReverse`。
10. **slide 子节点顺序**：`cSld → clrMapOvr → transition → timing → extLst`。
   `timing` 写在 `clrMapOvr` 之前会被 Office 判为结构错误。
11. **每次应用后跑 `fix_names.py` 与 `preflight.py`**；需要更严格验证时再用微软
   Open XML SDK 的 `OpenXmlValidator` 检查，目标版本至少应覆盖 `Office2013`。

## 推荐节奏

- 底色/背景：0.6~0.7s fade，随后 6~10s Ken Burns。
- 主视觉圆环：0.9~1.2s `zoom_soft`，随后 12~18s `rotate`。
- 巨号数字/英文：0.8~1.0s `cinematic`。
- 主标题：0.7~0.8s `zoom_turn` 或 `float`。
- 卡片/正文：0.4~0.6s，同组间隔 80~120ms。
- 一次点击后整页自动播完；总入场时长通常 1.8~3.2s。

## 跨页无缝：固定锚点 + Morph（"镜头不动、景物在变"）

用户说"丝滑切换上下页 / 上下页交互 / 多页连成一个动画"时，用这套机制，不要靠加更多形状。

### 结构
| 层 | 做法 |
|---|---|
| 锚点 | 全片一个圆形影像窗，**坐标尺寸恒定**（如 960×540 画布下 CX=792, CY=246, D=428） |
| 影像 | 程序合成的氛围图（暗红丝绸+斜光+颗粒），`prstGeom prst="ellipse"` 裁圆 |
| 结构 | 细金弧 `arc`、同心环 `ring`、半透明巨号数字——全部细线，不抢主视觉 |
| 文字 | 左侧固定区：PART 胶囊 → 双行大标题 → 金线 → 英文副标 |

### 为什么能"无缝"
Morph 按 `cNvPr@name` 匹配形状。同名 + 同坐标 + 同尺寸 → 插值恒等 → 圆窗**完全不动**，
只有圆内不同名的元素做交叉淡入。视觉上就是镜头固定、景象在流转。

### 转场节奏
- 内容页 → `morph` / `spd=slow` / `p14:dur=1800`
- 章节页 → `wheel8` / `slow` / `p14:dur=1300`（光圈扇形扫过，复刻参考片）
- 封面 → `circle`（从中心展开）
- 结尾 → 锚点放大到铺满（D→1000+），"穿窗而入"

> ⚠️ `morph` 只在 PowerPoint 2019/365 生效，WPS / PowerPoint 2016 会退化成硬切。
> 只要"锚点必须肉眼可见地移动"，就不能只靠 morph —— 用下一节的 `carry` 接力。

### 编排要点
- 圆内结构错峰 120~160ms 出场，`wheel`（扫出）/ `zoom`（展开）/ `fade`（浮现）
- 左侧文字 `float` 上浮 900ms，逐行 +60ms 微错峰
- 章节页巨号数字：`fade` 1400ms，透明度 90%，"极慢浮现"比快速弹出高级
- 圆窗图片**绝不**加 `kenburns`/`pulse`（会与金环错位）

### 程序合成影像（scripts/make_window_bg.py）
放弃"假装照片"（剪影/褶皱会变成栅栏和迷彩）。只做：
径向渐变（焦点暖金→暗红→近黑，gamma 2.0）+ 1~3 条极细光丝（exp 衰减、不弯曲）+ 8bit 抖动 + 颗粒。
暗角**从圆心算**，焦点推到圆外——否则圆内永远是最亮的中心。

## 锚点左右交替：让圆窗"横穿画面"滑过去

固定锚点做到极致会撞上另一堵墙：**每页构图完全一样，看三页就腻**。
用户的原话是"那个圆的图一直在右边，改成下一页丝滑旋转到左边来，多样式转换会变得很高级"。

### 做法
把圆心在左右之间交替，其余全部镜像。960×540 画布：

| 版式 | 圆心 CX | 文字栏 TX | 直径 |
|---|---|---|---|
| R（奇数页） | 792（出血右 46） | 62 | 428 / 章节页 404 |
| L（偶数页） | 168（出血左 46） | 440（= 960-62-458） | 428 |
| 封面 | 792 | 62 | 488 |
| 结尾 | 480（居中） | 251 | 1080（铺满） |

参数化写法（`gen7.py`）：

```python
def set_side(side, d=428.0, arot=None):
    global CX, CY, D, TX, AROT
    D, CY = d, 246.0
    if side == "R":
        CX, TX, AROT = 792.0, 62.0, (-12.0 if arot is None else arot)
    elif side == "L":
        CX, TX, AROT = 168.0, 960.0 - 62.0 - 458.0, (12.0 if arot is None else arot)
    else:
        CX, TX, AROT = 480.0, 251.0, (0.0 if arot is None else arot)
```

### 为什么不能用 morph 做这件事（血泪）
`p14:morph` 只有 **PowerPoint 2019 / Microsoft 365** 认。WPS、PowerPoint 2016 及更早版本
会直接**退化成硬切**——圆在切页瞬间就出现在新位置，用户看到的是"跳"，不是"滑"。
（第一版就是栽在这里：XML 完全正确、preflight 通过，但用户那边根本没动。）

所以位移必须写在**动画层**里，任何播放器都执行：

| 手段 | 说明 |
|---|---|
| 转场 `cut` | 硬切，不产生中间态。**不要**用 fade/zoom，会和接力位移打架 |
| `carry` 入场 | 每页的圆窗内核从"上一页圆心"滑到"本页圆心"，`dx/dy` 用画布比例 |
| `turn` 入场 | 弧线只转不缩，边滑边拧（配 `carry` 用） |
| 强调 `sway*` | 保留，但 delay 放到接力结束之后 |

### carry 的实现
```python
# anim_engine.py
if effect == "carry":
    dx = float(extra.get("dx", 0)); dy = float(extra.get("dy", 0))
    _set_visible()
    _motion(f"M {dx:.5f} {dy:.5f} L 0 0")     # 相对路径：从偏移处走回原位
    if extra.get("scale"):                     # 直径不同则同时缩放
        _scale(from_pct=int(extra["scale"] * 1000), to_pct=100000)
```

- 相对路径 `pathEditMode="relative"` 里 **1.0 = 一个画布宽**（和 `fly_l` 的 `M -1 0 L 0 0`
  同一套坐标），所以 `dx = (上一页圆心x - 本页圆心x) / 画布宽`，y 除以画布高。
- 路径第一点是 `(dx, dy)`、终点是 `(0,0)`：形状**先被摆到上一页的位置，再滑回编排位置**。
- `scale` 处理封面 488 → 内容 428 → 章节 404 的直径差，起步那帧尺寸正好接上前一页。

### 哪些形状要 carry
**圆窗内核是一个整体，漏一个就穿帮**（照片滑走了、弧线还留在原地）。按几何自动选：

```python
内核 = [形状 for 形状 in 页 if 圆心距 < 半径*0.92 and 不是 "bg"]
图形 → carry（图片、金环、弧线、环、点）
文字 → 延迟到接力结束后再浮现（大号数字、CONTENTS 这类）
```

末页圆铺满整屏时圆心距判定会失效，要特判成"只取 core 系"。

### 三个必须一起改的细节
1. **删掉内核原有的入场效果**：`zoom_turn` / `wipe_r` / `spin` 都带缩放，
   和 carry 同时跑会变成"一边滑一边从 0 放大"，非常怪。只留 `sway*`。
2. **其余元素整体后移**：`delay = max(delay + 380, 760)`，让圆先走完大半。
   否则文字会在圆还压在上面的时候就浮现。
3. **带 `scale` 时尺寸要跟着插值**：封面 488 vs 内容 428，不缩放的话切页瞬间圆会"缩一下"。

### 还是想加旋转
弧线的 `sp.rotation` 按左右给 ∓12°（arc 的包围盒以圆心为中心，rotation 就是绕圆心转），
这样每页的"光圈朝向"不同；进场时再配 `turn` 转满 360°，观感是光圈边滑边拧。
圆窗图片只给 `0.3 ×` 偏置（±3.6°），产生一点纵深差，不像整块贴纸在平移。

### 出血是加分项，不是 bug
`CX=792, D=428` → 右边界 1006 > 960，圆被裁掉 46pt；左版对称。
这是因为**只保留 62pt 外边距**，圆才有"压边"的编辑感。若全塞在画布里，
两侧会各留 100pt 空白，反而像没排满。只要保证被裁的是同一条弧、不切到文字就行。

### 走位：别让同一个圆在同一个位置来回
左右交替只能解决"永远在右边"，做久了会撞上第二堵墙：**同一个圆、同一个大小、来回横移**，
看起来像自动播放的模板。真正有效的是给每页一个**不同的 (圆心, 直径)**，让运动变成
斜向推进 + 推拉，而不是一条水平线。

| 版式 | 圆心 / 直径 | 观感 | 适合 |
|---|---|---|---|
| 全高压边 | (792, 246) / 428 | 圆切在画面边缘，稳 | 目录、列表页 |
| 大裁切 | (812, 262) / 540 | 一大片弧压过来，压场 | 章节页 |
| 小孔 | (210, 360) / 330 | 完整的圆浮在角落，克制 | 观点/宗旨页 |
| 偏心大圆 | (150, 300) / 480 | 重心下移，画面倾斜 | 流程/卡片页 |
| 铺满 | (480, 270) / 1080 | 照片满版，穿窗而入 | 结尾 |

排的时候盯两个数：**相邻页的位移**和**直径比**。位移 0.6 画布宽以上才明显；
直径比在 0.8~1.6 之间变化，才有"推近/拉远"的感觉。两者都变的段落最耐看。

本片实测（10 页）：

| 段 | dx | 直径变化 | 运动性质 |
|---|---|---|---|
| P1→P2 | +0.650 | 488→428（114%） | 横滑 + 略缩 |
| P2→P3 | −0.671 | 428→540（79%） | 横滑 + 大幅放大 |
| P3→P4 | +0.627 | 540→330（164%） | 斜向下 + 猛拉远 |
| P4→P5 | −0.606 | 330→404（82%） | 斜向上 + 放大 |
| P5→P6 | +0.669 | 404→480（84%） | 斜向下 + 放大 |
| P6→P7 | −0.615 | 480→340（141%） | 斜向下 + 拉远 |
| P7→P8 | +0.596 | 340→440（77%） | 斜向上 + 放大 |
| P8→P9 | −0.650 | 440→428（103%） | 横滑 |
| P9→P10 | +0.325 | 428→1080（40%） | 冲向满版 |

还有一个容易忽略的点：**大圆的巨号数字要按直径缩放**（`字号 = 118 × d/404`），
写死 118pt 的话，大裁切页里数字显得小、小孔页里又会溢出。

### "只有一个圆在变" — 把主体拆成四层叠加

走位解决的是"动起来不单调"，但停下来看还是**一个图形**。用户的原话是
"光有一个图形在变化太单调，添加圆或者别的图形重叠，视觉上有更大冲击"。

单个圆再怎么缩放/位移，视觉重量是恒定的。要的是**层数**。四层结构（自下而上）：

| 层 | 名称 | 做法 | 作用 |
|---|---|---|---|
| ① 底圆 | `spot` | 实心同色圆，透明度 9%，偏移 60~120pt | 露出的一角让主体"后面还有东西" |
| ② 主圆 | `coreImg` | 照片裁圆 + 外环 + 内环 + 内弧 | 视觉锚点，跨页 carry 的就是它 |
| ③ 伴圆 | `moon` | **实心深色盘**，直径 0.36~0.52× 主圆 | 明暗对比，两圆相交出月牙 |
| ④ 细轨 | `orbit` | 0.8pt 细环，1.10~1.20× 主圆，偏心 | 打破主圆的完整轮廓 |

三个关键判断：

1. **伴圆必须是实心的，不能是第二张照片**。两个淡色照片圆叠在一起只会糊成
   "肥皂泡"——没有明暗差就没有重叠感。深色实心盘 + 浅色主圆才有"蚀像"的重量。
2. **伴圆的圆心要落在主圆边缘附近**（距离 ≈ 主圆半径 × 0.95）。只取方向、统一距离：
   太靠里变成盖住主圆的补丁，太靠外变成两个无关的圆。代码里就是这么归一化的。
3. **动效上分两拍**：主圆先 carry 滑到位，伴圆再用 `iris`（圆形展开）"开光圈"，
   细轨用 `zoom`，数字用 `zoom_turn`。一次全出来就没有层次了，
   而且 carry 阶段伴圆还不存在 —— 这也顺便解释了为什么伴圆不能进内核。

⚠️ 预览器的坑（已修，别再踩回去）：伴圆在 `coreImg` 的外接框之外，carry 合成时会
被当成背景的一部分**在硬切那一刻就出现在终点**，而圆窗的裁剪图层里又会带上一块伴圆碎片
跟着缩放 —— 画面上就是**两个伴圆**。正确做法三条一起做：
① `bloom_boxes()` 把 spot / moon 的框读出来；
② 裁圆窗用的源图先把伴圆**抹掉**，抹掉的填色不能是纸色（那块在圆内，会留白斑），
   要沿同一方向取圆内 0.8r 处的像素；
③ 合成完圆窗后，把 moon 的圆形裁片**原样压在终点**（它是本页固定元素，圆窗滑到它下面）；
   spot 则不能压上来 —— 它本来就在圆窗下面。



### 中国风改版：厚环段 + 书法字体 + 山水视差

用户拿着参考图要求"圆环要叠加成镜头卡口、要跨页丝滑穿过去、背景换成青绿山水、标题用毛笔字"。
四条硬经验：

1. **厚环段 = 粗描边的弧**，不要用 `blockArc`。`blockArc` 的 adj3（内径比）在不同渲染器里
   解释不一致；给 `arc` 一个 20~45pt 的线宽，就是一圈带厚度的环段，端点还是平的，
   和参考图里的"镜头卡口"完全一致。
2. **环段的缺口要朝向文字栏**。环的直径是圆的 1.7 倍，往文字那边一伸就横穿正文。
   按圆心位置定缺口方向：右半页的圆 → 缺口 180°（左手边），左半页 → 0°。
   三圈环各给不同弧长（约 280°/266°/248°），再叠一条更淡更宽的"叶片"压在照片上。
3. **环要进 carry 内核并配 turn**。只画在页面上，翻页时环会留在原地；
   进 `CARRY_NAMES` 后它跟着圆一起滑、并转满 360°，观感就是"同一组环在页间转着穿过去"。
   每页再给不同的起始角（`idx * 47`），缺口位置逐页错开，不会像一套贴纸重复。
4. **中文字体必须写 `a:ea`**。`run.font.name` 只生成 `<a:latin>`，而汉字字形由
   `<a:ea typeface="...">` 决定 —— 不补这一条，书法体/宋体全部失效，中文永远落在主题默认字体上。
   族名用英文（STXingkai / STZhongsong / LiSu），中文名在 OOXML 里不一定解析得到。

视差：底图拆成"远山（不透明）+ 近山（顶边羽化透明）"两张，分别做 `kenburns` / `drift`，
速度不同就是"远近变化"。整页再压一层 16% 的雾白当 veil，山色会退到文字后面去。

### 走位解决"动"，装饰层解决"页边"，但主体还只有一个

运镜丰富了，可每页停下来看，画面仍然只靠**一个圆**撑着。第二层要加的是**页边细节**——它们不抢主体，
但会让版面从"一张图 + 一段字"变成"一套排版系统"。

| 元素 | 名称前缀 | 做法 | 作用 |
|---|---|---|---|
| 虚焦光斑 | `blob` | 半径 190~240 的柔光圆，压在空角落 | 大块死黑不再"空"，像镜头进光 |
| 对焦刻度 | `tick` | 圆周外 13pt 处沿 92° 弧排 21 根径向短杠（每 5 根一长） | 把圆变成"镜头"，有精密感 |
| 四角取景标 | `cnr` | 距边 30pt 的 16pt 直角细线，4 角 × 2 段 | 像相机取景框，把版面框住 |
| 脊线竖排字 | `vlabel` | 贴左右边缘、`rotation=270`、7.5pt | 杂志刊头味，补足边缘的"薄" |
| 章节进度轨 | `rail` | 4 段 24pt 短杠 + `0N / 04` | 给读者"我在第几章"的锚点 |

四条实现纪律：

1. **追加在每页内容之后**。装饰放在最后画，已有形状的 id 全部不变，
   `plans.json` 里手写的 spid 才不会错位。为了加装饰去重排 id 是纯亏。
2. **装饰不进 `carry` 内核**。它们都在圆外，跟着 `carry` 的 `scale` 走会散开
   （`animScale` 是绕形状自身中心缩放，不是绕圆心）。正确做法：让它们
   **等接力结束再浮出来** —— 光斑 fade 1200、刻度每根错 24ms 扫过去、
   角标 fade、进度轨 `wipe_r`，时间基准统一取 `CARRY_MS + 120`。
3. **放不下就不放**。出血页（d=540，上下都切）圆周外没有任何空位，
   刻度环要整页跳过；装饰密度每页不同，反而比十页一个样耐看。
4. **刻度环的方向**：未旋转的细条长轴是竖直的，转到方位角 `ang` 要 `+90°`
   （`sp.rotation = degrees(ang) + 90`），而且**不要**再叠加弧线的 `AROT`，
   否则刻度不再指向圆心。

两个踩过的坑，直接记住结论：

- **`spc`（字距）会吃字**。7.5pt 小标签设了 `spc` 之后，LibreOffice 在组边界断行、
  再把第二行裁掉：`2026` 渲染成 `202`、`参赛手册` 渲染成 `参赛手`，
  看着像字体缺字，其实是布局。**细小标签一律不设 `spc`**。
  （同理：`railno` 的 `01 / 04` 被切成 `01 / 0` 也是这个原因，不是框太窄。）
- **柔光斑不要用 `a:gradFill path="circle"`**。LibreOffice 会在形状边界留一圈硬边，
  像个"饼"；PowerPoint 里又正常 —— 两端不一致最难查。改**预生成径向渐变 PNG**
  （圆心不透明、`(1-t)^2.4` 衰减到全透明）+ `a:alphaModFix` 控强度，
  所有渲染器都是同一张图，不可能有边。

### 出血抠图时的补边（做预览才需要）
圆切到画布外时，那一条内容在源渲染里根本不存在。补法要"接缝连续、向外淡出"：
- 直接拉伸一整条 → 竖直糊痕 + 一道硬线；
- 镜像 → 把数字和金环复制一份，出重影；
- **取最边 1 列拉伸 + 叠一条由实到透明的渐变** → 接缝连续、远端融进黑底，最自然。

## 旋转 / 缩放语言（"翻页时东西在转，转完又摆回来"）

用户说"动画太平""要旋转缩放""要上下页互动"时，纯 morph 交叉淡入是不够的——它只换画面，
不产生位移运动。用下面三层叠出立体感。

### 第 1 层：转场（整页在动）
| 转场 | 观感 | 适用 |
|---|---|---|
| `zoom` + `transition_ms` 1200 | 整页从中心放大翻入 | 内容页，最像"翻页" |
| `wheel8` + `transition_ms` 1300 | 8 个扇区旋转扫过 | 章节页，仪式感 |
| `morph` + `p14:dur` 1600~1800 | 圆窗位置恒定、景象流转 | 封面 / 结尾 / 需要"无缝"的页 |

三种交替＝有节奏，全程同一种会腻。

### 第 2 层：入场（元素自己在转/缩）
| 效果 | 动作 | 适合 |
|---|---|---|
| `zoom_turn` | 72%→100% + 由 -8° 转正 + 淡入 | 标题、卡片、徽章——最通用的"转正" |
| `cinematic` | 上浮 3.5% + 86%→100% + 由 -3° 转正 | 副标、说明、巨号数字（配 1600ms 慢推） |
| `spin` | 0→100% + 转满 360° + 淡入 | 弧线、圆环、光点——"旋着展开" |

### 第 3 层：持续（转过去又回来）
| 效果 | 动作 |
|---|---|
| `sway6/10/15/20` | 绕自身中心往复摆 ∓N°，`autoRev=1` + `repeatCount=indefinite` |
| `rotate` | 单向 360° 循环，适合光圈/进度环 |
| `breathe` | 缩放 ±4% 呼吸 |

**关键**：`sway` 的 delay 必须晚于入场结束（`入场delay + 入场dur + 200ms` 起），
否则会被入场动画覆盖，看不到摆动。弧线用 `sway10`、奖项圆用 `sway6`、别超过 15°（会歪）。

### 为什么弧线能绕圆心转
`a:prstGeom prst="arc"` 形状的包围盒是以圆心为中心的正方形，PowerPoint 的旋转绕包围盒中心，
所以对弧线施加 `sway`/`rotate` 就是**绕圆心转动**——光圈转起来了，不会飞出圆外。

### 预览器注意事项（render_gif.py）
自绘预览有几个已修的坑，改动时别回退：
- 未编排进 plan 的元素必须返回"静态可见"状态，否则背景/圆窗图片整层被跳过（白底、图片消失）。
- `geom="arc"` 要单独用 `ImageDraw.arc` 画，缺分支会退化成矩形。
- 存 GIF 必须 `optimize=False, disposal=1`：旋转帧差异大，开优化会把旧区域清成背景，
  观感是"转着转着画面没了"。

### 预览器注意事项（render_deck.py，真实渲染版）
它不是自绘，是 LibreOffice 出图再合成，保真度高得多，但"锚点横滑"的合成有五个坑：
0. **按 carry 合成，不要按 morph 合成**：读 `plan` 里第一条 `carry` 的 `dx/dy/scale/dur`，
   从"上一页圆心 + 偏移"滑到"本页圆心"，底色在前 16% 帧内硬切。
   用 morph 的"两页同时插值"会让文字和圆同时双曝光，跟实际播放完全不一样。
1. **出血抠图必须补边**：`_circle_layer` 裁的是锚点外接框，框越出画布时那部分内容在源页
   根本不存在。不补边 → 图层是透明的 → 圆滑到画面中间露出一块"洞"，洞后面是下一页，
   叠成一道生硬竖边。用 `_extend_edge` 按最近像素做水平/垂直拉伸（照片是柔和渐变，看不出缝）。
2. **交叉溶解只能改 alpha**：`Image.blend` 两个 RGBA 会把透明区的黑混进 RGB，
   圆边缘出现一圈脏色。正确写法是 `alpha_composite(_fade(b, tb), a)` —— a 保持不透明，
   只压 b 的 alpha，结果 alpha 恒为 1。
3. **文字与圆窗的淡入要解耦**：文字层提前淡完，圆窗全时长滑行。
   同速淡会全程双曝光，"PPT 设计大赛"和"四个篇章"叠在一起，像重影不像转场。
4. **擦除多涂一圈，贴回也要多涂一圈**：金环描边正好压在椭圆边界上，擦除不带 pad 会留
   半圈残影；但 pad 让擦除圆大于贴回圆，又会留一道淡色细缝。两边用同一个 `pad = max(3, w*0.018)`。
5. **底色不能写死成近黑**：`_erase_circle` 原来 `bg=(10,7,8)`、`_circle_layer` 的底也是
   `(10,7,8)`——那是深色片的底色。做浅色片（米白 / 白）时，挖洞和出血补边会补出一块
   **近黑**，圆窗一滑开就露出黑斑，看着像画面糊了。正确做法是 `_paper(img)`：
   沿四条边取 44 个点、量化到 8 的格子后取众数，得到"这一页的纸底"，
   深色片自然得到近黑、浅色片得到米白，出血页也不会取偏。
   **判断标准：换一套配色就重跑一次预览，别假设底色。**

### 深色片不要交付 GIF
GIF 只有 256 色，近黑的大面积径向渐变无论怎么处理都会坏：
- 每帧各自 `convert("P")` → 暗部逐帧跳色，看起来在闪；
- 共享调色板 + Floyd 抖动 → 出现满屏噪点，比色带更脏；
- 不抖动 → 整块色带，像画面脏了一块。
**结论：直接出 mp4。** `render_deck.py --mp4 out.mp4` 走 ffmpeg 管道（rawvideo → h264），
960px/30fps/33s 只要 7MB，渐变干净。编码器按 `libo264rt → h264_amf → h264_mf` 回退。
